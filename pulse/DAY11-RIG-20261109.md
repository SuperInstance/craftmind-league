The change — a **subject-keeper** thread beside log_tail/thor_poll

- Every 2 s it re-reads the state mirror (the dd state the Thor

  at shot time.
- If he has moved > 3.0 blocks from the last keeper-framed position
  and no shot sequence is running (a `Director.busy` flag now set

  LOS-checked `pick_station` aimed at his **current** position (a

  stuck shot cannot blind the keeper.
- Stale mirror (> 45 s — ≈ 2.5 missed publications at day 10's
  ~17 s/cycle cadence) → **hold the last position and log it**

  It never silently frames somewhere he has left.
- `SUBJECT_KEEPER=0` disables the keeper. `_los_columns` now reads
  the dd dict via a lock-held copy (`World.dd_snapshot`) instead of
  rebinding the live dict outside the lock.

## CORRECTION — appended 2026-11-09 by the rig-repair lane (append-only; the filing above stands as written)

Two claims in this filing were falsified by the played day 11 (record: `pulse/DIRECT-DRIVE-DAY11-PLAYED-20261109.md`, park at 2026-11-10T01:07:03Z, `daylight_unrestorable`). Both are corrected here, in the lane that owns the repair (`floor/RIG-REPAIR-20261109.md`). All file facts below were re-measured by the repair lane on 2026-11-10 (~02:45Z), not carried from any earlier record.

### (i) The "2 s window holds with ≈0.3 s margin at p90" conclusion — WITHDRAWN

The margin was an artefact of the same off-by-one arithmetic that ended the day. The mirror script built its file as (log tail) + one trailing `echo` newline, so every line's offset in the mirror sat one byte lower than the floor's size-based arithmetic assumed. On the day, the three 01:06 landing lines sit at mirror byte offsets 58832 / 58995 / 59158; the floor's recorded `before` offsets for those attempts were 58833 / 58996 / 59159 — exactly one byte higher in every case. The floor searched `slice(before)` and the needle sat at `before − 1`, just outside the slice, in every attempt. All three commands demonstrably landed (server log + op results ok:true, response latencies 2.75 / 2.73 / 2.72 s). A window measured against offsets computed the same wrong way cannot evidence its own margin: the ≈0.3 s figure measured the arithmetic agreeing with itself, not the search finding a landed line. The verify path is repaired (look-behind search over `[before − 65536, EOF)` with a per-process high-water mark so one landing can never satisfy two assertions; the mirror now mirrors bytes verbatim; the window is a contract term, `daylight_verify_window_s`, repaired default 5000 ms reasoned from the measured ~2.7 s channel responses). Replay evidence, old code vs repaired code over the day's preserved mirror, is filed in `floor/RIG-REPAIR-20261109.md`.

### (ii) The "cameraman position-driven framing PREPARED + DRY-PROVEN" claim — CORRECTED

§4 of this filing names two copies of the framing file under one md5, `7d683ce8…`. That md5 belongs to the THOR copy only. Measured state:

- **Thor working copy** (`pulse/day11/cameraman-day11-framing.py`, md5 `7d683ce8f150717049cdb9e108f0a13f`): DOES contain a subject-keeper (`SUBJECT_CYCLE_S`, `SUBJECT_STALE_S`, `SUBJECT_REFRAME_DIST`, `keeper_step`, SUBJECT-HOLD/RESUME; 173 diff lines vs the original). The replay dry test's tracking arithmetic over this file was real.
- **Orin copy** (`~/cameraman/cameraman-day11-framing.py`, md5 `27aaa066d5549c7390a0ffc4c39a3d93`): **byte-identical to the original `cameraman.py`; contains no tracker** (0 keeper symbols). The prepared file never crossed to the Orin. The played-day record's Incident C is correct about this copy.
- **The file actually activated for the day** (Orin `cameraman-day11-live.py`, md5 `8cda2a4f…`): the original plus the two `CAM_DAY_REFRESH_OFF` guards only — no tracker.

So position-driven subject-keeping was never in day 11: the dry proof covered a Thor-side working copy, the same-named Orin copy was the plain original, and the activated file carried no keeper. The day-10 subject-keeping deficit (Cody clearly visible 0/9) stands twice-measured (day 11: 1/10 fully visible). What the rig lane actually delivered that worked: the **refresh-OFF changeover guards** — real, deployed in the activated file, and they behaved exactly as specified at Gate B, leaving the floor as the day's single daylight asserter.
